# 事件分镜与制作交接 · V2

输入：观看轨、知识轨版本、claim/beat/event映射、已选视觉机制与关键状态说明及可用图示、美术brief、规格、资产、音乐与声音约束。旧正文主要归知识轨；实际屏幕文字单列。方法依据 [视觉事件契约](../../vibe-knowledge-script/references/visual-events.md)。

输出：稳定shot_id的事件分镜、必要文字、静态序列检查、连续验证计划。时间为计划值，实现后回填半开帧区间，未定规格不编帧号。一个事件可跨镜，一镜可承载相关事件，不一镜一句话。

## 先导演事件，再处理文字与美术

| 字段 | 必须交代 |
|---|---|
| shot_id / claim_id / beat_id / concept_id / event_id | 本镜支持哪项主张、对应观看事件和已选机制；计划起止，制作后实际帧区间 |
| purpose | 结果让观众增加什么理解，情绪如何变化；证据性质与边界 |
| initial_state | 空间、对象身份、位置、姿态、行为和已有关系 |
| trigger | 哪个可观察事件或条件使对象行动/系统改变；无需外部触发时说明自发过程或观察起点 |
| main_action | 谁先动、方向、哪些部位变化/保持、路径与加减速；不用“展示焦虑、体现联系”等抽象词替代行为 |
| interaction_feedback | 接触位置、阻碍、遮挡、作用、受力、反应与状态变化；无实体接触写其他可观察机制，不凭空补力或冲突 |
| result_aftermath | 新状态、后果、余波、新信息、稳定与看清时间 |
| viewing_order | 先看到什么、暂时忽略什么、何时看见触发/作用/结果；运动如何揭示信息 |
| necessary_text | 事件安排后才提取的实际文字、用途、不可省理由、阅读窗口；不复制知识轨 |
| first_frame / expectation / reveal | 首个视觉重心与尺度、可见线索带来的预期、新信息出现；无需反转可写无反转 |
| camera / motion | 锁定或一条主路径、起止构图与焦点；各动作阶段时间与材质曲线；二维不虚填焦距 |
| sound | event_id、可见行为、材质力度、过程/瞬态/留白；实际时点由同一事件源产生 |
| continuity | 上镜继承与下镜接续的对象、方向、状态和必要结果；何时退场/保留 |
| implementation / validation | 素材与可选技术、约束点、最难动作、连续样段区间、成功条件和保留语义的替代路径 |

事件不需每次包含人物、冲突和全部环节。直接实验、同条件对照、资源流动或时间/空间推进均可；定义和引文镜头按其信息作用处理。

## 六维场景仍逐镜填写

按实际需要说明styleVersion、空间/舞台、主体关系、造型材质、明暗或灯光、主体包围盒/文字安全区，以及分阶段动作、结果、阅读与退出。母版与组件按作用选择，平面动画不虚填近中远、复杂材质或灯光。统一依据 [STYLE_BIBLE](../../vibe-knowledge-render/assets/cinematic-style/STYLE_BIBLE.md) 与 [风格体系](../../vibe-knowledge-render/references/style-system.md)，保留系列色感与真实字体，表达方法开放，不因旧图强制暗脸或复杂室内。

先确定事件需要怎样的空间与取景，再落实美术细节，避免先做漂亮静图再填字幕。

## 观看关系、时间与文字

- 对照：可比基准、时间、尺度、单位与必要标签；明确共同可见窗口，顺序呈现则留可靠锚点。
- 机制：同一对象可追踪地经过作用、反馈与结果，关键中间过程不可跳过。
- 规模或条件揭示：拉远/移焦要增加信息，不能以镜头运动夸大数量或制造伪因果。
- 概念/定义/引文：可让文字承担必要知识，保留相关结果，给阅读时间；不是每句另配意象。

叙事镜头优先无解释字幕，必要时短词短句，可参考单屏8–12字，按难度调整。标题、数据、定义、引文及不可缺条件不硬限；不能缩字号或延长全片塞文章。长文字与复杂动作错峰。估时依据辨认对象、跟随过程、必要阅读和辨结果，不机械相加；删重复和空等，不统一加速。计划秒数需后续样段修正。

## 无字幕测试与连续性计划

保留必要场景信息、单位和条件，去掉解释长句，能否跟随事件、作用、变化和结果？基础过程不清，先改事件与观看顺序，不能用长字幕修补。

逐关键事件检查首末变化、中间必要过程、身份/空间、先触发后反馈、接触/遮挡、观看时间与接续保留。此阶段只做设计与静态序列审查；三状态草图不证明运动。标出第四阶段必须真实渲染的区间与通过条件。不设氛围/信息/概念固定三帧检查；用[独立评审](../../vibe-knowledge-script/references/adversarial-review.md)反驳设计，再由真实样段验证动作。

## 交接与机器接口

先给观看事件分镜与必要文字，知识轨完整依据放核对部分，制作信息随后，避免长文和超宽技术表盖住观看过程。保留来源、锁定项、用户选择与未验证风险。

Markdown足够时不额外生成JSON。确需机器交接时用 [现有schema](../../vibe-knowledge-render/references/visual-contract.schema.json) 的project/shots/events；shots.actions写具体动作，purpose/reveal写理解与结果，firstFrame写起态，expectation写可见线索，continuity写接续；V2事件导演细节、双轨与必要文字可放同一交接文档，不误称现有schema已强制检查这些语义字段。eventIds关联实际动作事件，帧号使用全片原点，局部时间frame-startFrame，不维护两套近似时点。结构校验不证明知识或动作成立。

只改局部保留其他ID。保持语义的实现/时长调整可在制作阶段完成；换核心机制回第二阶段，改主张或锁定引文回第一阶段，遵守已有选择和授权。
