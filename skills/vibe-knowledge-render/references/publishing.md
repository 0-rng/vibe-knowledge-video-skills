# 封面与发布简介

完整视频制作时，把封面和简介作为正式交付；仅写脚本、总结方法或修改技能时不生成这些素材。用户只要其中一项时保持任务范围。

## 封面图

交付实际 PNG 或 JPG 图片，不能只给封面提示词、设计建议或未经排版的抽帧。可以选取成片中有代表性的清晰画面再排版，或用同一视觉系统专门绘制；沿用本片角色、颜色、品牌和关系含义。

- 提炼一个核心问题或冲突。主标题简短易读，必要时配一行副标题；不要把完整简介塞进封面。
- 画面应让观众快速认出主体及关系。不要用无关夸张元素承诺视频没有讲到的内容，也不要把有条件的研究结论改成绝对断言。
- 依据目标发布位置与已知裁切方式确定尺寸。未指定时先采用与成片一致的画幅，关键标题和主体集中在安全区域；不把某个固定尺寸宣称为平台统一规定，不自动输出多种尺寸和大量方案。
- 品牌沿用用户已确认的位置与写法。没有授权的活动标志不自动加入。
- 实际查看图片，按手机缩略图尺度检查中文文字、对比、主体辨识度与裁切风险。封面单独预览，方便用户判断。

## 可直接填写的简介

这里的“简介”默认指本条视频的发布说明，不是账号个人简介。先给一版可直接粘贴的成稿，避免只教用户“可以写什么”。通常用两到四句，随内容调整：

1. 用与故事有关的问题或具体处境引入。
2. 说清视频探讨什么，保留适当悬念，同时不误导研究结论；虚构演绎需要时用一句自然说明。
3. 适合时用一个与内容有关的问题邀请讨论，避免机械要求点赞、关注和转发。

后附少量直接相关的话题标签，通常三到五个即可。活动标签只在用户明确参加该活动、或已核实适用要求时加入；“参考某活动画风”不等于实际参赛。声称符合当前字数、活动或发布规则前先核实，不编造规则。

发布标题、封面主标题可以根据展示长度适度不同，但主题与承诺一致。音乐许可要求的署名按原条款写入；知识来源需要展开时可给一段简短补充说明或置顶评论建议，不默认附技术报告。未经核实不要编造曲作者、研究出处或权威背书。

## 呈现顺序

完整制作的回复优先展示视频与封面，然后直接列出发布简介和标签。无需把独立音轨、时间轴、源码或工程包当作附赠交付。只准备发布素材，不自动上传、发布或修改账号资料。

每个实际交付文件另给单独可点击的 Markdown 链接，目标为本地绝对路径，标签写清“视频”“封面”“发布文案”等用途。预览、文件名或文件夹路径不能代替文件链接。仅交付分析报告或提示词时，同样附对应文件链接。
