# 四阶段独立反驳与优化

用户已授权在每个创作阶段使用一个独立子智能体审查演绎效果与视觉观赏性。形成可评审初稿后默认执行：`初稿 → 独立反驳 → 主创核对并修改 → 针对修改处复查 → 展示优化结果`。这是内部质量检查，不增加用户审批；只改错字、整理文件或改技能时不机械跑四遍创作。

## 调用与独立性

- 使用当前环境真实的子智能体工具，例如`collaboration.spawn_agent`。主创负责整合；评审只读，不代选、不改文件、不生成媒体、不发外部消息，也不继续派生评审。
- 给最新用户要求、阶段、知识依据与边界、已选项、当前初稿和可访问的实际图片/视频路径。尽量使用独立上下文，只提供必要材料，不灌输主创自评、预设优点或期望结论。
- 要求从观众立场提出最有力的反例：拿掉解释长句还发生什么；事件是否支持主张；哪里无聊、含混、僵硬或被装饰淹没。不凑问题数量，不以个人偏好否定事实或用户选择。
- 工具不可用、素材不可读或评审失败时如实记录，不用主创换口吻冒充独立意见。可做明确标为主创自检的修改；没有证据的结论仍待验证。

## 各阶段审查重点

| 阶段 | 输入 | 主要质疑 | 证据上限 |
|---|---|---|---|
| 内容 | 来源、候选/双轨稿、事件链 | 是知识演绎还是换词讲道理；行为与结果怎样支持发现；有无只有对白、没有可看变化的情境；是否越过依据 | 只能评内容依据、演绎潜力与设计风险，不能断言画面已好看 |
| 视觉 | 观看轨、机制、状态说明及已有实际图 | 第一眼能认出什么；状态有何差异；互动是否清楚；隐喻是否靠长字幕硬连；造型和背景是否过复杂 | 无图只评设计；静帧不能证明动画流畅 |
| 导演 | 分镜、动作阶段、计划时长与可用图 | 是否缺中间过程；姿态/接触/视线/阅读是否可执行；停顿是否有效；接续是否推进理解 | 评观看顺序与连续性设计，标出需样段验证区间 |
| 制作 | 实际样段/成片、事件和必要文字、检查范围 | 动作是否真的发生；主体是否清楚；有无穿插、僵硬、空等、假运动；节奏与结果是否兑现知识 | 只对实际看到的材料下结论；连续帧、实时播放、试听分别记录 |

观赏性用具体证据讨论：重心与对比、造型辨识、姿态与衔接、预期与反馈、节奏变化、结果的观看时间。复杂度、写实度、粒子和电影术语不是加分项；简化人物、平面图解、稳定背景都可成立。没有观众实测不保证喜欢或留存提升。

## 可复制的评审任务

```text
你是独立的演绎与视觉评审，只读审查本阶段初稿。
阶段：[script / visual / storyboard / render]
用户要求、已选项、依据与边界：[最小必要上下文]
初稿及实际可访问材料：[正文或绝对路径，注明版本]
请独立检查：主要知识是否通过可观察事件推进；画面/设计是否清楚且有观看吸引力；什么具体证据会推翻主创判断。
每条意见写：对应claim/beat/concept/shot/event或时点、材料证据、影响、可执行改法、怎样复查。
区分阻断问题、改进建议、待验证；无材料时注明证据不足。
不要只表扬、强找问题、虚构播放/试听/观众测试，或要求恢复固定三张图。
不改文件、不启动媒体生成、不代替用户选案，不再派生子智能体。
```

## 反驳、修订与停止

主创逐条核对：采纳的写清修改，未采纳的给具体依据或用户要求；不能以旧图或旧契约为理由拒绝合理简化，也不盲从会扭曲事实的建议。优先修最影响理解和观看的少量问题。

默认一次评审和针对性修订；修改关键事件后交评审复查同一节点。通常最多两轮，问题已解决即停。连续两轮同一缺陷无改善，换表达/实现或报告缺口；核心事件未成立不得标完成。改变用户已选主张或核心机制时，先形成具体可比较的替代，再按已有选择授权处理，不重开无关阶段。

交接保留紧凑记录：`阶段/版本 → 真实评审任务标识 → 关键反驳和证据 → 采纳/未采纳理由 → 修改 → 复查结论/未验证部分`。用户默认只看重要修改和剩余问题，不倾倒内部长评或虚构质量分数。评审不能代替真实渲染检查或用户创作选择。
