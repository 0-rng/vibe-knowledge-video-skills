# 双轨剧本结构与表达 · V2

本文件负责内容组织；共同规则见 [视觉事件](visual-events.md)，视觉机制见 [第二阶段](../../vibe-knowledge-visual/references/content-visual-mapping.md)，镜头展开见 [第三阶段](../../vibe-knowledge-storyboard/references/director-storyboard.md)。

## 原稿归知识轨，保留锁定项

先记下用户的问题、重心、关键句、顺序和引文位置。已有正文是编辑及核对依据，完整解释进入知识轨；不是现成字幕表。若明确要求保留屏幕原句，则单独锁定，不借事件化改写原意。用户只要文章时按范围交稿，不额外制作影片。

用户指定多层解释时各层保留认识增量；一个方便制作的手机故事不能接管全部论证。内容语义先于现成组件。

## 研究与发现→情境/机制→事件链→核对→必要文字

每项知识主张先说明依据和边界，再寻找能观察的行为、机制、同条件对照或结果。不存在可见过程时查找真实例子、实验或适合模型；定义、引用等本来需要文字的内容可以直接显示，不为了演起来造因果。

候选节点用`起态 → 触发/实际变化 → 反应/新结果 → 下一步原因 → 认识增量`。关键节点通常3–6个，按题材增减，不凑数，不预先决定镜头数和秒数。自然事件发展优于角色轮流说金句；现实或虚构情境须标证据性质，情境不能证明主张。

## 选定后的双轨交付

- **知识轨**：完整逻辑、必要解释、依据、引文、反例与事实边界。连读仍成立，开头的问题与结论相互兑现。
- **观看轨**：观众实际看到的事件、动作、可观察结果，以及不可省的有限文字。通过claim_id、beat_id、event_id指回知识轨，而不是逐句配镜。

可用紧凑表：`主张/依据 → 起态 → 动作/反馈 → 结果/下一步 → 新理解 → 必要屏幕文字及理由 → 情境性质`。具体资产、构图和执行动作留后两阶段；事件语义不提前替用户锁定视觉机制。

## 文字与无旁白

无旁白不要求字幕独立复述完整论证。先使主要关系、过程和结果可见，文字留下命名、定义、关键条件、数据、引用及结论。不可缺限定必须在实际观看轨中有效表达，不能仅在知识轨稿后撤回绝对断言。

语言具体，有对象、条件和结果，不堆术语。复杂过程不同时叠长文字；是否用短词、读多久由导演与制作验证。字数与时长为计划，压缩先删重复与无效等待，不删必要条件，不靠统一加速。

## 自检

知识轨检查论证、引用与真实性；观看轨暂时去掉解释长句，检查事件能否被跟随，以及结果是否支持对应认识。两轨合起来完整传达知识，不要求任何一轨单独承担全部任务。检查观看轨不是知识轨全文复制，也不是独立金句合集；无实测不许诺留存提升。
