# 内容交接：知识轨与观看轨 · V2

交接放在现有brief或剧本中，不默认增加机器文件。四阶段共用 [协作](workflow.md) 和 [视觉事件契约](visual-events.md)。

## 第一阶段交什么

引用双轨版本与确认状态，保留题目、核心问题、一句发现、观众处境、叙述情绪、开头承诺与结尾兑现。

- 知识轨：完整逻辑、解释、来源、引用位置、反例和事实边界；旧正文保留在此。
- 观看轨：逐事件的起态、动作/作用、反馈、新结果、下一步为何发生和理解增量；优先供第二阶段设计。
- 关联：claim_id / beat_id / event_id、对应知识主张、证据性质、必要屏幕文字及不可省理由。标真实事件、研究结论、典型情境、虚构演绎、假设模型或视觉隐喻，不能以情境证明普遍因果。
- 锁定：用户原句、论证顺序、引文位置、明确屏幕文字、规格、旁白、品牌和音乐版本。知识轨全文不是锁定字幕；用户明确的屏幕原句仍保护。

## 第二阶段继续决定什么

将观看事件转成可信视觉机制，比较对象、状态、作用及结果，说明核心动作起态、过程与结果，按判断需要补实际图示，不固定三格。内容阶段提出的事件语义不预先锁定资产、道具或镜头，未选隐喻不能变成下游默认。

第二阶段以知识轨核对条件、主张和真实性，不能直接把它拆成字幕。发现事件无法支持主张，返回第一阶段修内容；不能为了漂亮画面偷换观点或让单例接管复杂论证。

## 选择、版本与范围

分清用户锁定、代理推荐、待选和未核实。新选题保留3–5方向供选，选定后深化双轨；第二阶段视觉选案、第三阶段导演选案继续保留，只有明确授权代选才跳过相应等待。已有选择不重复询问。

有成熟正文、概念或分镜时复用，只补影响当前决策的双轨缺口。只要求编辑文章不自动制作事件影片；用户授权制作且设计门槛通过后才进入第四阶段。
