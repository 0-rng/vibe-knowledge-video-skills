# Vibe 视觉创意关联内容 · 视觉事件驱动 V2.1

设计能发生且能被观察的视觉机制。先读 [视觉事件共同契约](../vibe-knowledge-script/references/visual-events.md)、[风格体系](../vibe-knowledge-render/references/style-system.md) 与唯一 [STYLE_BIBLE](../vibe-knowledge-render/assets/cinematic-style/STYLE_BIBLE.md)。保持暗色系列基础与真实字体，按内容选择造型、对比、层次和运动；从当前知识重新选择对象、动作与结果，不从漂亮物件反推观点。

## 独立反驳与优化

形成本阶段可评审初稿后，默认开启一个独立子智能体，按[评审流程](../vibe-knowledge-script/references/adversarial-review.md)质疑演绎效果与视觉观赏性；主创核对反驳、修订后复查关键节点，再展示结果。不得用自评冒充独立意见，或用静帧证明动作流畅。通常最多两轮，核心问题未解决如实交代。只改技能或零碎勘误不机械运行四阶段。

旧三张参考图不再作为创作或验收基准；取消固定三帧确认门槛。需要图时按当前问题选择数量与形式，不凑三类图、不靠旧图锁定人物、场景或表现手法；已有用户选择与制作授权边界继续保持。

## 输入与边界

优先读取第一阶段**观看轨**及其事件链，以**知识轨**核对依据、条件、引用与边界；同时读取已选方向、版本和用户锁定项。只有旧正文时先将知识与必要屏幕文字分开，补最小事件语义；缺核心发现或证据则返回`$vibe-knowledge-script`，不代写新立意。

跨阶段和局部修改读 [协作](../vibe-knowledge-script/references/workflow.md)。新片默认横屏16:9、1920×1080、30fps，已有规格优先。本阶段交实际静态候选与机制，不制作动画或声音；静态状态设计不等于已验证连续动作。已有选案沿其范围发展，不重开全片选择。只改技能不生成图片。

## 先做知识到视觉转换

按 [关联与转换](references/content-visual-mapping.md)，逐关键发现写`claim/beat/event → 必须保留的关系与条件 → 表达类型 → 对象状态与变化 → 结果 → 新理解 → 必要文字 → 证据性质/误读`。先尝试实际对象、行为、机制、同条件对照或可操作模型；使用隐喻时仍需事件与结果支持对应关系，不能靠字幕强行解释道具。

人物情绪优先考虑行为、选择及后果；机制呈现作用过程；抽象系统可操作；数据有来源与尺度；认知偏差先形成可见预期再揭示；历史保留时间空间事件；哲学用困境与选择帮助思考。不是每题都用人物、粒子或三维，也不让光点距离、镜子、门、书和连线成为模板。

## 研究、机制候选与八问

按 [概念比较](references/visual-concept-director.md) 和 [画面选案](references/visual-options.md) 检索操作、现象、视觉艺术和动画参考，记录`来源启发 → 本片转换 → 差别与风险`。复用前阶段资料并补视觉决策缺口，不照搬某影片画风。用户参考先实际查看。

开头、核心机制与重要转折比较机制不同的候选，同一节点不重复凑数，按分歧给足可比较的方向，通常2–3案，已选和局部任务不重新凑案。可比较现实事件、机制模型、对照实验或其他真正适题的方式，不强制三类齐全。每案回答：

1. 第一眼是什么具体对象？
2. 有哪些可识别状态？
3. 对象之间有什么关系？
4. 什么动作或作用改变关系？
5. 变化如何发生、先后怎样？
6. 观察哪个结果后能理解知识？
7. 哪些文字仍不可省，为什么？
8. 当前素材与技术能否可信实现，哪里待验证？

每案还给内容对应、情绪、来源、优势、误读、失败征兆与推荐理由。换颜色、材质、道具或发光不算机制不同，易做不成为默认选案理由。

## 起态、动作中、结果的实际画面

每套方案明确`起始状态 → 关键变化 → 结果状态`，说明状态间发生什么。用状态说明、关键姿势或按需图示使核心过程可判断，不强制生成三格或固定数量；用户要看画面时交实际候选，不以文字敷衍。静态图用于检验对象、状态和语义，不证明速度、接触或动画已经成立。

需要素材时读`$imagegen`，只生成无字背景或独立元素；图形可用统一组件程序绘制。重要中文、轴名与微UI真实字体合成。实际展示结果，不交提示词冒充图像；用户明确只要文字时按其范围交状态设计并标明尚无图。横屏统一构图，不能用占位草图冒充精美资产，也不虚构本地图片路径。

## 淘汰与选定

有以下问题先重做：核心关系依赖大段解释字幕；只有美丽静态构图；道具联系靠文字硬连；状态变化不支持主张；关键动作无可信实现路径。资产方法尚待试做可具体标风险，已知无法兑现的方案不可当可用方案推荐。定义、数据或必要条件本来需要文字时不机械去字。

逐案标识concept_id，展示状态说明、必要图示、取舍与推荐，等待用户选择；一般完整策划不授权代选，已有选择或明确授权则沿用。用户未选前不展开完整导演表。

选定后交视觉主张、知识到视觉映射、关键状态序列、对象身份、美术brief、实际图像引用、必要文字、资产状态和风险。用`beat_id / event_id / concept_id`关联观看轨，注明不能改变的关系、可替换素材及表达损失。项目要求见 [项目偏好](../vibe-knowledge-script/references/account-profile.md)，落实资产见 [素材方法](../vibe-knowledge-render/references/direction-and-assets.md)。

## 风格校准与交接

完整分镜交`$vibe-knowledge-storyboard`。按未解决的视觉分歧提供必要静态材料，数量和类型由问题决定；不要求氛围、信息、概念三图，不把静态选图变成永久风格锁。独立评审给出设计风险，实际运动交制作样段验证。用户只要组件或静帧时按该范围执行。

交付前暂时去掉解释长句：基础事件与结果是否仍可追踪？若需知识轨全文才能把画面串起来，返回机制设计；若主张本身失真回第一阶段；若观看顺序不清交第三阶段。来源边界见 [导演来源](../vibe-knowledge-script/references/director-sources.md)。
